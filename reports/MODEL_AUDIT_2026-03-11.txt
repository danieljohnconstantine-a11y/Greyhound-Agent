  Previous run (before fix) emitted warnings:

  User demanded explanation and fix.

ROOT CAUSE:
  The CalibratedClassifierCV(method='sigmoid') wrapper was applied to GB AFTER
  the GB model had already been trained.  Gradient Boosting's predict_proba()
  is natively well-calibrated (Friedman 2001, §10.13).  The sigmoid (Platt
  scaling) layer maps GB raw-logit outputs through 1/(1+exp(a*f+b)).  When:
    - Training data class imbalance ≈ 12.5% positive (1 winner per 8 dogs)
    - sigmoid a ≈ 0 (because GB raw probs cluster tightly near the prior)
  the sigmoid function compresses all inputs to a narrow band around 0.11-0.12,
  regardless of how discriminative the raw GB predictions were.

  XGB suffered the same issue. XGB's own sigmoid output converts internal
  logits to probabilities; the second CalibratedClassifierCV sigmoid layer
  then double-squashes the output.

FIX APPLIED (2026-03-11):
  1. MODELS (immediate fix):
     For each of the 3 tracks, the base GradientBoostingClassifier and
     XGBClassifier were extracted from inside the CalibratedClassifierCV
     wrapper and saved directly as the model .pkl files.  RF keeps its
     CalibratedClassifierCV(sigmoid) since RF outputs class votes (not probs)
     and genuinely benefits from Platt scaling.

  2. train_ml_track_ensemble.py (permanent fix for future retrains):
     - GB: removed CalibratedClassifierCV wrapper; learning_rate 0.05→0.10,
       added min_samples_leaf=3, subsample=0.8 for better separation.
     - XGB: increased learning_rate 0.05→0.10, added subsample=0.8,
       colsample_bytree=0.8; kept CalibratedClassifierCV(sigmoid) since XGB
       truly does output logits (not calibrated probabilities).

  3. retrain_all_tracks_sigmoid.py train_track() (consistent with above):
     - GB: removed CalibratedClassifierCV wrapper; learning_rate→0.10,
       added min_samples_leaf=3, subsample=0.8.
     - XGB: learning_rate→0.10, added subsample/colsample_bytree=0.8.
