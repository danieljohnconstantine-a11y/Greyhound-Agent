  ANSWER TO Q2: WHAT IS CALIBRATION COLLAPSE AND WHY DOES IT HAPPEN?
══════════════════════════════════════════════════════════════════════════════

  Short answer:  A "calibration collapse" means the model assigned the
                 same (or nearly the same) probability score to EVERY dog
                 in the race — making it impossible to pick a winner.
                 It happened because of a mathematical double-correction
                 that squeezed all scores into a tiny band.  It has been
                 fixed.  Here is the full explanation:

──────────────────────────────────────────────────────────────────────────────
  STEP 1 — WHAT IS CALIBRATION?
──────────────────────────────────────────────────────────────────────────────

  Every prediction model (RF, GB, XGB) outputs a raw probability — a
  number between 0 and 1 representing "how likely is this dog to win?"

  A fresh Gradient Boosting (GB) model might output:
    Dog in Box 1:  0.23  (23% chance)
    Dog in Box 2:  0.18  (18% chance)
    Dog in Box 3:  0.09  ( 9% chance)
    … and so on.

  "Calibration" is a post-processing step that adjusts these raw numbers
  so they better match real-world outcomes.  The industry-standard method
  is called sigmoid calibration (also known as Platt Scaling).

  Think of it like turning a dial to fine-tune the volume of a radio signal.

──────────────────────────────────────────────────────────────────────────────
  STEP 2 — WHAT WENT WRONG (the double-correction)
──────────────────────────────────────────────────────────────────────────────

  Gradient Boosting (GB) and XGBoost (XGB) already produce well-calibrated
  probability estimates internally.  They don't need extra calibration.

  The previous code was applying a SECOND calibration layer on top anyway.
  This is like turning the radio dial twice — the second turn almost always
  over-corrects and cancels out the first adjustment.

  The mathematical result:  the sigmoid function is shaped like an "S".
  When the input values all cluster near 0.11–0.12 (roughly 1/8, because
  there are 8 dogs in a race), the S-curve maps them ALL to nearly the
  same output — typically 16.07%.

  So instead of:
    Box 1: 23%    (clear favourite)
    Box 2: 18%
    Box 3: 9%
    …

  The collapsed model output:
    Box 1: 16.0711%
    Box 2: 16.0712%    ← all almost identical, useless for ranking
    Box 3: 16.0710%
    …

  This is calibration collapse.  Every dog looks equally likely and the
  model cannot pick a winner.

──────────────────────────────────────────────────────────────────────────────
  STEP 3 — WHY DID THE DETECTION TRIGGER?
──────────────────────────────────────────────────────────────────────────────

  The code checks two conditions before using any model's predictions:

    a) TRUE collapse:   More than half of the dogs have EXACTLY the same
                        probability value.  (e.g. 5 out of 8 dogs all scored
                        exactly 0.16071).

    b) NEAR-collapse:   All dogs' scores are within 0.5 percentage points
                        of each other.  (e.g. scores range from 16.07%
                        to 16.08% — a spread of only 0.01%).

  The 0.5% threshold means: "if the best dog's score minus the worst dog's
  score is less than half a percentage point, the model cannot reliably
  rank the field."

  When either condition fires, the code:
    1. Prints a warning with the ⚠️ symbol.
    2. Falls back to the model's internal, uncalibrated predictions
       which retain the original discrimination.

──────────────────────────────────────────────────────────────────────────────
  STEP 4 — HOW WAS IT FIXED?
──────────────────────────────────────────────────────────────────────────────

  FIX (applied 11 March 2026 — see reports/MODEL_AUDIT_2026-03-11.txt):

    • Gradient Boosting (GB):  the second calibration layer was REMOVED.
      GB's own predict_proba() is already well-calibrated.  It now outputs
      spread values of 25–38% across a race field.

    • XGBoost (XGB):  same fix — second calibration layer removed.
      Now outputs 11–14% spread, well above the 0.5% threshold.

    • Random Forest (RF):  KEPT its calibration layer.  RF votes by
      majority — its raw output is NOT a probability and genuinely needs
      calibration.  RF is not affected by this issue.

  RESULT (from reports/MODEL_AUDIT_2026-03-11.txt):

    Track        Model  Spread before fix  Spread after fix  Status
    ───────────────────────────────────────────────────────────────
    Angle Park   GB     0.08%              24.77%            ✅ OK
    Angle Park   XGB    0.17%–6.1%         13.39%            ✅ OK

    GUNNEDAH     XGB    0.28%              14.32%            ✅ OK

  Zero collapse warnings in the 11 March 2026 pipeline run.

──────────────────────────────────────────────────────────────────────────────
  STEP 5 — WILL IT HAPPEN AGAIN?
──────────────────────────────────────────────────────────────────────────────

  It should not happen for any track retrained with the new code.

  The retrain_all_tracks_sigmoid.py script has been updated so that:
    • GB is trained and saved without a calibration wrapper.
    • XGB is trained and saved without a calibration wrapper.
    • RF retains its calibration wrapper (correct by design).

  The collapse DETECTION code in run_track_ensemble_predictions.py remains
  in place as a safety net.  If an old model with the double-calibration
  bug is ever loaded, the guard will catch it, fall back to the uncalibrated
  predictions, and print a warning telling you exactly which track needs
  retraining.

  In short: the guard is a symptom detector.  The root cause is fixed.

    spread scores from ~10% (clear outsider) to ~35% (strong favourite).
