Great question — short answer: we cover a lot of this now, but not 100% yet.

Current status by item:

1) Split Times & Early Sectional vs Overall Time
✅ YES (mostly)
- We use SectionalSec, EarlySpeedIndex, EarlySpeedPercentile, TimeVsField, SpeedVsField, PaceBoxFactor, and InterferenceRisk.
- This already gives strong early-speed and race-shape signal beyond final time.

2) Track Bias & Surface Condition Changes (moisture/weather/maintenance)
⚠️ PARTIAL
- Track box-bias and upset factors are included.
- SurfacePreferenceFactor exists (sand/grass heuristic).
- But live weather/track-condition variant is NOT fully integrated in main training flow (TrackConditionAdj remains neutral in core path).

3) Box Draw Map Interferences / Run-Style Clashes
✅ YES (mostly)
- Implemented via pace map + neighbor pressure + contested lead logic + InterferenceRisk + CompetitorDensity/Adjustment.

4) Trainer/Kennel Form Cycles + Short Rest
✅ YES (good coverage)
- TrainerStrikeRate + TrainerMomentum + DLR/FreshnessFactor + DLW/WinStreak factors are in model features.

5) Grade Transitions & Class Drops
⚠️ PARTIAL
- GradeFactor, RTCFactor, ClassRating are included.
- But explicit class drop/rise delta (current grade vs avg last 3 grades) is not fully built as a dedicated transition feature yet.

6) Straight-to-Circle Transitions (RICS vs RICH etc.)
⚠️ PARTIAL
- Track-specific modeling and separate straight/circle track handling exist (e.g., Richmond vs Richmond Straight, Murray Bridge vs Murray Bridge Straight).
- But explicit dog-level transition feature (recent straight -> now bend, and vice versa) is not yet a dedicated engineered feature.

Bottom line:
- Strongly covered: 1, 3, 4
- Partially covered / next upgrades: 2, 5, 6

If you want, next step I can implement these missing pieces directly:
(1) true weather/track-variant adjustment in training,
(2) explicit class rise/drop delta feature,
(3) explicit straight↔circular transition feature per dog.
