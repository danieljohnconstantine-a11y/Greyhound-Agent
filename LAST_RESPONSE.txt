Plain-English explanation of "overrides" and prediction impact

You asked:
"What does auto-load model_tuning_overrides.json mean? What override? Will this improve predictions?"

1) What "override" means

Normally, train_ml_track_ensemble.py uses built-in default settings for each model.
Example defaults are things like:
- RandomForest: number of trees, tree depth, min samples split
- GradientBoosting: learning rate, min samples leaf, subsample
- XGBoost: number of trees, learning rate, depth, subsample, colsample

An "override" just means:
- If file exists: best_bets_reports/model_tuning_overrides.json
- then training uses the values in that file INSTEAD of hardcoded defaults.

So:
- with file present -> use override values
- with file missing -> use normal defaults

No other behavior changes.

2) What override values are currently being applied

From current generated file, profile = conservative.
Current values are:

RandomForest
- n_estimators: 100
- max_depth: 8
- min_samples_split: 8

GradientBoosting

- subsample: 0.75

XGBoost
- n_estimators: 120
- learning_rate: 0.08
- max_depth: 3
- subsample: 0.75
- colsample_bytree: 0.75

This is more cautious than aggressive settings.

3) Will this improve predictions?

Honest answer: it may improve robustness, but no guaranteed lift every run.

Most likely benefits:
- Less overfitting to noisy races
- More stable probabilities
- Better generalization when race mix changes

What it does NOT guarantee:
- It does not guarantee higher win rate in every period/day.

Best way to verify improvement:
- Train once with overrides
- Backtest on recent unseen dates
- Compare to prior model on:
  - top-pick win rate
  - top-3 strike rate
  - calibration by gap buckets

4) Simple rule to remember

- override file present = tuned params used
- override file absent = default params used

So yes: best_bets_reports is now part of the training workflow via that override file.
