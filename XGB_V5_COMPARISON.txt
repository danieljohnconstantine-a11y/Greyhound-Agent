│ v5 Improvement #2-4: Triple Regularization                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ #2: reg_alpha=0.01 (L1 Regularization - Lasso)                              │
│     • Encourages sparse solutions                                            │
│     • Feature selection effect                                               │
│     • Formula: Loss + 0.01 × Σ|weights|                                     │
│                                                                              │
│ #3: reg_lambda=1.0 (L2 Regularization - Ridge)                              │
│     • Smooths weights                                                        │
│     • Numerical stability                                                    │
│     • Formula: Loss + 1.0 × Σ(weights²)                                     │
│                                                                              │
│ #4: gamma=0.1 (Minimum Split Loss)                                          │
│     • Controls tree complexity                                               │
│     • Only split if gain > 0.1                                               │
│     • Prevents unnecessary splits                                            │
│                                                                              │
│ Combined Impact: +1-2% accuracy                                              │
│ Why Together: Complementary regularization approaches                        │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ v5 Improvement #5: scale_pos_weight (Class Imbalance)                       │
├─────────────────────────────────────────────────────────────────────────────┤
│ What:    Automatically balances positive vs negative classes                │
│ Calc:    scale_pos_weight = n_negative / n_positive                         │
│                                                                              │
│ Example:                                                                     │
│   Non-winners (negative): 850 samples                                        │
│   Winners (positive):     100 samples                                        │
│   Ratio: 850 / 100 = 8.5                                                    │
│                                                                              │
│ Effect:  Each positive sample counts as 8.5× in loss function               │
│                                                                              │
│ Why:     Winners are rare (~10-15% of data)                                  │
│          Without this: Model learns "always predict non-winner"              │
│          With this: Model pays attention to both classes                     │
│                                                                              │
│ Similar to: RF's class_weight='balanced'                                     │
│ Impact:  +1-2% accuracy                                                      │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ v5 Improvement #6: min_child_weight=2                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│ What:    Minimum sum of instance weight needed in a child node              │
│ Why:     Prevents overfitting on very small leaf nodes                      │
│                                                                              │
│ Similar to: RF/GB's min_samples_leaf=2                                       │
│                                                                              │
│ Effect:                                                                      │
│   ✗ Cannot create leaf with <2 weighted samples                             │
│   ✓ Forces leaves to have minimum evidence                                  │
│   ✓ Better generalization                                                    │
│                                                                              │
│ Impact:  +0.5-1% accuracy                                                    │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ v5 Improvement #7: colsample_bylevel=0.8                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│ What:    Sample 80% of features at EACH level of tree construction          │
│                                                                              │
│ Comparison:                                                                  │
│   colsample_bytree=0.8   → Sample 80% features PER TREE                     │
│   colsample_bylevel=0.8  → Sample 80% features PER LEVEL (NEW v5)           │
│                                                                              │
│ Tree structure example:                                                      │
│                                                                              │
│   Level 0:  [A, B, C, D, E, F]  → Sample 80% → [A, C, D, F]                │
│   Level 1:  [A, B, C, D, E, F]  → Sample 80% → [B, D, E, F]                │
│   Level 2:  [A, B, C, D, E, F]  → Sample 80% → [A, B, C, E]                │
│                                                                              │
│ Result: Different features at each level = more diverse tree structure      │
│ Impact: +0.5-1% accuracy                                                     │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│ v5 Improvement #8: max_delta_step=1                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│ What:    Maximum step size for weight updates                               │
│ Why:     Prevents extreme probability predictions                            │
│                                                                              │
│ Without max_delta_step:                                                      │
│   Weight updates can be unbounded                                            │
│   Can lead to probabilities: 0.0001 or 0.9999                               │
│   Overconfident, poorly calibrated                                           │
│                                                                              │
│ With max_delta_step=1:                                                       │
│   Weight updates capped at ±1                                                │
│   More gradual convergence                                                   │
│   Better calibrated probabilities: 0.1-0.9                                   │
│                                                                              │
│ Especially useful for: Imbalanced datasets (our case!)                       │
│ Impact: +0.5-1% accuracy                                                     │
└─────────────────────────────────────────────────────────────────────────────┘
