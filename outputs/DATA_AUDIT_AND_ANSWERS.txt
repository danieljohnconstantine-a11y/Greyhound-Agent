QUESTION 1: IS ALL DATA FACTUAL? IS ANY DATA CREATED/FABRICATED?
================================================================================

SHORT ANSWER: ✅ All prediction-relevant data is factual and extracted from the

  Dogs audited:    1,098
  Dogs with data mismatches: 0 (after parser fix — see Question 3)
  Fabricated values: NONE

WHAT IS EXTRACTED DIRECTLY FROM PDF (100% factual):
  • Box           — draw position from race table
  • DogName       — dog's registered name
  • Trainer       — trainer name
  • SexAge        — sex and age (e.g. "3b" = 3-year-old bitch)
  • Weight        — racing weight (kg) — NOTE: form shows 0.0kg for SA dogs,
                    which is factual; SA does not publish weights
  • CareerWins    — career win count from "W - P - S" column
  • CareerPlaces  — career place count
  • CareerStarts  — total career starts
  • PrizeMoney    — total prize money ($)
  • RTC           — Racing Times Category (km of racing in 14 days)
  • DLR           — Days Last Race
  • DLW           — Days Last Win (or "Mdn" if maiden/no win)
  • BestTimeSec   — fastest time at this distance, extracted from race history
  • SectionalSec  — fastest sectional time, extracted from race history
  • Distance      — race distance (metres)
  • Draw          — box draw number

WHAT IS COMPUTED FROM PDF DATA (mathematical transforms only):
  • Speed_kmh     = Distance / BestTimeSec × 3.6
  • PlaceRate     = (CareerWins + CareerPlaces) / CareerStarts
  • WinRate       = CareerWins / CareerStarts
  • DLWFactor     = f(DLW) — freshness from days since last win
  • RestFactor    = f(DLR) — rest factor from days since last race
  • BoxBiasFactor = track-specific box statistics (from training data)
  • TrainerStrikeRate = trainer wins / trainer starts across this race card
  • FormMomentum  = direction of recent race margins (SET TO 0 — margins not
                    parsed by current parser; this is a known limitation, not
                    fabrication — all dogs get 0 equally, no bias introduced)
  • All other features = mathematical transformations of the above

DEFAULT VALUES (where PDF data is absent — applied equally to all dogs):
  • TrackConditionAdj = 1.0  (neutral — track condition not in modern form PDF)
  • WeightFactor      = 1.0  (neutral — SA form does not publish weights)
  • FormMomentum      = 0.0  (neutral — margins not parsed; all dogs get same)

VERDICT: 100% of prediction-relevant fields are factual. Defaults are neutral
and applied equally to all dogs, so they create no bias between dogs.

QUESTION 3: WAS THERE A DATA ISSUE? (IMPORTANT — READ THIS)
================================================================================

YES — a pre-existing parser bug was found and fixed in this PR.

BUG DESCRIPTION:
  Some dogs in the race form PDF have their career record (W - P - S) split
  across 3 lines in the PDF text:

    Line k  :  "37 - 43 -"           ← wins=37, places=43 (split mid-record)
    Line k+1:  "1. 13112Kisauni 3d 0.0kg 1 Ryan Tugwell $160,880 118 7 14"
    Line k+2:  "117"                  ← career starts=117

  The parser was misreading the "118 7 14" on the dog line as
  CareerWins=118, CareerPlaces=7, CareerStarts=14 (instead of RTC=118,
  DLR=7, DLW=14), and the real career record was lost.

SCOPE OF BUG:
  44 dogs affected across 8 of the 13 PDFs (ANGLG, GEELG, GOSFG, MANDG,
  MTGG, NOWRG, QPRKG, QSTRG, SHEPG, WNBLG).

DOGS AFFECTED IN RACE 8:
  • Kisauni: was CareerWins=118, now CORRECT CareerWins=37 (37-43-117)
    RTC was 0, now CORRECT RTC=118 (heavily raced — 118km in 14 days)
  • Victory Club: was CareerWins=28, now CORRECT CareerWins=21 (21-41-101)
    RTC was 0, now CORRECT RTC=28

IMPACT ON PREDICTIONS:
  With correct data, Kisauni moves from 5th → 2nd (31.6% win rate, fast
  30.24s best time, heavily raced at 118 RTC, just 7 days since last race).

FIX APPLIED:
  src/parser.py — added pre-processing step that detects the split pattern
  and reconstructs the dog line with correct career stats before parsing.

AUDIT COMMAND: `python data_integrity_audit.py --pdf ANGLG0503form.pdf`

QUESTION 4: DO I NEED TO RETRAIN MODELS?
================================================================================

SHORT ANSWER: NO — you do NOT need to retrain models to use this system.

EXPLANATION:
  The models (Angle Park_rf.pkl, Angle Park_gb.pkl, Angle Park_xgb.pkl) were
  trained on historical greyhound race data with 76 input features. These
  models are stable — they encode learned patterns about what wins at each
  track. The models do NOT need to be retrained every time you run predictions.

  You should consider retraining IF:
  • You want to add data from new tracks (BALLARAT models exist; other tracks
    like CASINO, GEELONG etc need training data to be prepared)
  • You want to incorporate results from the last 6-12 months of racing to
    improve accuracy
  • The current models' accuracy has degraded significantly over time

  The current Angle Park and BALLARAT models were trained on Dec 29, 2025 and
  remain valid for predictions. They will produce results for any Angle Park
  or BALLARAT PDF you place in data_predictions/.

  For 11 other tracks (CASINO, GEELONG, GOSFORD, MANDURAH, MT GAMBIER, NOWRA,
  Q PARKLANDS, Q STRAIGHT, SANDOWN, SHEPPARTON, WENTWORTHVILLE, WENTWORTH),
  models need to be trained. The pipeline will skip these tracks with:
    "⚠️  No models found for [TRACK], skipping"

HOW TO TRAIN NEW TRACK MODELS:
  Place historical result CSVs in the data/ folder and run:
    python train_ml_track_ensemble.py
  OR:
    train_ml_track_ensemble.bat

QUESTION 5: CAN I DOWNLOAD LATEST REPO AND COPY-PASTE MODELS FROM MY PC?
================================================================================

SHORT ANSWER: YES — absolutely. The models are portable .pkl files.

STEPS TO USE YOUR LOCAL MODELS:
  1. Download/clone the latest repo:
       git clone https://github.com/danieljohnconstantine-a11y/Greyhound-Agent
       git checkout copilot/run-full-pipeline-test

  2. Copy your .pkl model files into the models/ folder:

     EITHER flat-file layout (original):
       models/Angle Park_rf.pkl
       models/Angle Park_gb.pkl
       models/Angle Park_xgb.pkl
       models/Angle Park_scaler.pkl

     OR subdirectory layout (new — after running ORGANIZE_ALL_TRACKS.bat):
       models/Angle Park/rf.pkl
       models/Angle Park/gb.pkl
       models/Angle Park/xgb.pkl
       models/Angle Park/scaler.pkl

     Both layouts are supported automatically. If you have flat files,
     run reorganize_models_by_track.py to migrate to subdirectory layout.

  3. Place today's PDF race forms in data_predictions/

  4. Run predictions:
       run_track_ensemble_predictions.bat   (Windows)
       python run_track_ensemble_predictions.py  (any OS)

IMPORTANT MODEL COMPATIBILITY NOTE:
  The models require scikit-learn==1.8.0 and xgboost>=2.0.
  If you get a version warning, run:
    pip install --upgrade scikit-learn==1.8.0 xgboost

  The models are CalibratedClassifierCV wrappers. The pipeline now
  automatically detects and bypasses calibration-collapse, so predictions
  will work correctly even when the calibration compresses probabilities.
